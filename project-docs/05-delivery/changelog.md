  - **Hosting:** backend, web and admin on Vercel. **ADR-012** (new) supersedes ADR-005: Express as a Vercel Function (`api/index.ts`); Socket.IO in its own function (`api/socket-io.ts`, path `/api/socket-io/socket.io`, websocket only); `@socket.io/mongo-adapter` + `mongo-emitter` on a TTL collection (no Redis); clients reconnect with backoff, refresh the token first and re-fetch `GET /notifications` after every connect; rate limiting moved to a MongoDB store (`RateLimit`, TTL index); Vercel Cron calls `/internal/cron/cleanup` daily (OTPs, refresh tokens, adapter documents), replacing `node-cron`; `TRUST_PROXY=1` in production; Prisma singleton and Atlas pool options documented; Vercel project settings for backend/web/admin.
  - **Deviation from the request (flagged):** Vercel Cron only makes `GET` requests and authenticates with `Authorization: Bearer CRON_SECRET`; it cannot send `x-cron-secret`. The cleanup route is `GET` (also `POST`) and accepts the Bearer header **or** `x-cron-secret`. Adapter collection is a TTL collection, not capped, because capped collections forbid deletes (cron cleanup needs them).
