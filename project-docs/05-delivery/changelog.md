## 2026-11-22 (AUTH-03 reset-password IP-limit flake root-caused and fixed)
- **Flake (noted in the T-021 entry) reproduced and fixed; no retries or timeouts added.** Repro: `tests/auth/reset-password.test.ts` alone 20×/20 green; full suite under load failed 1/10 runs at `AUTH-03 · successful resets do not count toward the IP limit` (`reset-password.test.ts:483`, `expected 429 to be 400` on the request right after the successful reset).
  - **Root cause:** `createRateLimiter({ skipSuccessful: true })` used express-rate-limit's `skipSuccessfulRequests`, which counts every request up front and refunds a successful one with an **unawaited MongoDB decrement in a `response.on('finish')` handler**. The refund races the same client's next request: under load the 10th failure after a success saw 11 un-refunded hits → 429. Not test-only — in production a client's follow-up request right after a success can be 429'd while still in budget. (Ruled out: per-test key wipe covers the shared `127.0.0.1` key; fake timers cover `Date`, which is all the store reads; T-024 keys cannot survive — the file has its own database.)
  - **Fix (`src/lib/rateLimit.ts`):** the inner limiter no longer uses `skipSuccessfulRequests`; `createRateLimiter` wraps `res.end` so a < 400 response awaits the refund decrement **before the response is sent** — once a client holds a success response, the refund is in the store. A refund failure is logged and the response is sent anyway (fail open); a failed-open request (nothing counted) skips the refund. Affects the `login` and `reset-password` IP limiters (AUTH-02 had the same latent race).
  - **Regression test (`tests/lib/rateLimit.test.ts`, NFR-01):** deterministic, via the existing `db.run` hook — every decrement is delayed 30 ms, then fail→success→fail at limit 2 must give 400/200/400 (and the counter must already show the refund right after the success response). Fails 100% on the old code (`expected 2 to be 1`), passes on the fix.
  - **Suite:** 594/594; typecheck, lint, format clean; 10× full-suite stability loop on the fixed code green.
